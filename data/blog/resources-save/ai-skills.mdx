## Skill 编写

[add-skill](https://github.com/vercel-labs/add-skill)

一个用于为编码智能体（如 OpenCode、Claude Code、Codex 和 Cursor）安装技能的命令行工具。技能通过包含 YAML 前言的 SKILL.md 文件定义，可扩展智能体的功能，例如生成发布说明或集成外部工具。工具支持从 GitHub、GitLab 等源码安装，并提供全局或项目级安装选项。

[Skill_Seekers - 制作 skill 的工具](https://github.com/yusufkaraaslan/Skill_Seekers)

[claude-skills - 生成 skill 的 skill - 元 skill](https://github.com/tukuaiai/vibe-coding-cn/blob/main/i18n/zh/skills/claude-skills/SKILL.md)

[skill-prompt-generator - 基于 Claude Code Skills 的智能提示词生成系统](https://github.com/huangserva/skill-prompt-generator)

[microsoft/skill-recorder - 将一次操作录制成可复用 Skill](https://github.com/microsoft/skill-recorder)

Microsoft 开源的桌面应用：录制一次真实工作过程后，它会借助 GitHub Copilot CLI 把屏幕操作还原为任务意图与有序步骤，并生成可复用的 `SKILL.md`，或创建按计划、触发器执行的 Automation。

- 不机械回放点击：产出的 Skill 会优先使用 `gh`、`web_fetch` 等 agent 原生工具，并从单次示范中泛化出可重复执行的流程。
- 适合沉淀个人操作经验：例如把某次表单提交、跨应用处理或网页操作，转成可审阅、编辑和持续复用的 agent 工作流。
- 有明确的数据边界：录制及本地处理默认在设备上完成；只有选择分析后，事件时间线、提取的屏幕图像、旁白文本等才会发送给 GitHub 云端处理，切勿录入密码、令牌、密钥或其他敏感信息。
- 运行条件：需要具备 Copilot 访问权限的 GitHub 账户；以 macOS 为主要目标，也支持 Windows 11，项目采用 MIT 许可证。

[colleague-skill - 把同事蒸馏成 AI Skill](https://github.com/titanwings/colleague-skill)

一个偏“人格 + 工作方式”建模的 Skill 生成器。它支持基于飞书消息、钉钉文档、邮件、截图和主观描述，生成可在 Claude Code / OpenClaw 中调用的“同事 Skill”，让智能体尽量复现某位同事的技术规范、表达风格和决策习惯。

- 不只是生成提示词：产物同时包含 Work Skill 和 Persona 两部分，强调“先按角色判断，再按能力执行”。
- 适合沉淀团队经验：能把某位同事的 code review 风格、接口规范、沟通方式和职场行为抽成可复用资产。
- 支持持续演化：可以增量追加材料、对话纠正设定，并保留版本以便回滚。

[nuwa-skill - 蒸馏任何人的思维方式](https://github.com/alchaincyf/nuwa-skill)

一个把“造 Skill”从同事扩展到任意公开人物或主题的方法型 Skill。它不是简单模仿名人语录，而是尝试从公开资料里提取表达 DNA、心智模型、决策启发式、反模式和诚实边界，再生成可调用的 `SKILL.md`。

- 更像“认知蒸馏器”：核心目标不是复制语气，而是沉淀一个人怎么想、怎么判断、什么不会做。
- 方法论写得比较完整：仓库把六路并行采集、三重验证提炼、Skill 结构模板和质量验证流程都公开了，适合拿来参考“人物/主题 Skill”怎么做才不空。
- 不只产出单个仓库：`nuwa-skill` 本身可安装使用，也给出了乔布斯、芒格、费曼、Naval、张一鸣等多个已蒸馏示例，便于直接看效果和反推设计方式。

## Skill 管理工具

[skills-npm](https://github.com/antfu/skills-npm)
skills-npm 是一个命令行工具，用于发现 npm 包中内置的智能体技能，并通过创建符号链接供编程智能体使用。该项目旨在解决现有技能分发方式中的摩擦，如仅支持 Git 源、版本不匹配和手动管理问题，提出将技能直接打包在 npm 包中的新约定。

[autoskills](https://github.com/midudev/autoskills)
autoskills 是一个自动安装 AI agent skills 的 CLI。它会扫描项目里的 `package.json`、Gradle 和配置文件，识别技术栈，再从维护者审核过的 registry 中选择匹配 skills，校验 hash 后写入本地，适合给项目快速补齐前端、后端、移动端、云基础设施和测试相关技能。

[skillman](https://github.com/pi0/skillman)
本文介绍了 skillman 工具，它是一个用于管理项目 Agent 技能的命令行工具，通过读取和操作 skills.json 文件来安装、添加来自不同来源的技能。

[rulesync](https://github.com/dyoshikawa/rulesync)
Rulesync 是一个 Node.js 命令行工具，旨在通过统一的 AI 规则文件，自动为多种主流 AI 开发工具生成配置文件。它支持选择性生成、全面的导入/导出功能，并能管理规则、命令、MCP 配置、忽略文件、子代理和技能，从而实现跨工具开发规则的一致性

[dotagents](https://github.com/iannuttall/dotagents)
这里可以集中管理您的所有钩子函数、命令行工具、智能技能以及 AGENT/CLAUDE.md 配置文件。

## Claude Code Skills

[claudeskill-loki-mode - Claude Code 多智能体自主启动系统](https://github.com/asklokesh/claudeskill-loki-mode)

[Agent-Reach - 给 Agent 装上全网搜索与阅读能力](https://github.com/Panniantong/Agent-Reach)

一个面向 Claude Code、OpenClaw、Cursor、Codex 等编码代理的联网 Skill + 安装器，目标不是自己包一层搜索服务，而是把 Twitter/X、Reddit、YouTube、GitHub、B 站、小红书、抖音、微信公众号、RSS 等渠道统一接进 agent 工作流里。

- 更像“联网能力总线”：安装后 agent 会直接调用各平台对应的上游工具，而不是被一个黑盒 wrapper 包住。
- 覆盖面很广：除了通用网页和 GitHub，还兼顾中文平台与内容源，适合做资料收集、竞品检索和多平台内容阅读。
- 对 agent 场景友好：既提供 CLI，也提供可安装的 Skill，适合在 Claude Code / OpenClaw 这类环境里按触发词自动调用。
- 成本门槛低：项目主打零 API 费用，更多是处理工具选择、安装和环境诊断，减少“明明能搜却接不起来”的配置摩擦。

[last30days-skill - 用“最近 30 天”视角做多源研究](https://github.com/mvanhorn/last30days-skill)

一个偏“时效性 + 社交信号”的 research skill。它会并行检索 Reddit、X、YouTube、TikTok、Hacker News、Polymarket、GitHub 和 Web，并按 upvotes、likes、赔率等真实互动信号排序，再由 agent 汇总成一份 brief。

- 不是普通搜索：重点不是抓更多网页，而是把分散平台里“最近 30 天真正有人讨论什么”拼起来，适合会前速读、人物近况、公司舆情、产品口碑和竞品观察。
- 安装路径清晰：Claude Code 推荐 `/plugin marketplace add mvanhorn/last30days-skill` 后执行 `/plugin install last30days`；Codex、Cursor、Copilot、Gemini CLI 等可用 `npx skills add mvanhorn/last30days-skill -g`。
- 默认即可用 Reddit、Hacker News、Polymarket、GitHub；想解锁 X、YouTube、TikTok 等来源，再补浏览器登录态或对应 key 即可。

[Waza - 面向完整工程师的 Claude Code Skills](https://github.com/tw93/Waza)

一个偏“少而精”的 Claude Code Skill 集合，围绕设计、排障、检查、写作、学习和资料阅读这些工程习惯设计，不追求大而全，而是把高频动作做成触发即用的稳定工作流。

- 技能集合克制：核心围绕 `/think`、`/design`、`/check`、`/hunt`、`/write`、`/learn`、`/read`、`/health` 等入口展开，适合不想维护庞大规则体系的人。
- 强调工程习惯而非功能堆叠：把需求挑战、系统化调试、交付前自检、英文表达和资料消化都沉淀成可复用动作。
- 安装门槛低：支持通过 `npx skills add tw93/Waza -g -y` 一键全量安装，也支持按单个 skill 单独安装。
- 适合做个人基线：如果已经在用 Claude Code，但还没有一套轻量、清晰、可长期维护的 skill 组合，Waza 很适合作为起点。

[agent-skills - Addy Osmani 的生产级工程 Skills](https://github.com/addyosmani/agent-skills)

一个面向 AI coding agents 的工程技能集合，围绕 DEFINE、PLAN、BUILD、VERIFY、REVIEW、SHIP 生命周期组织。它把需求澄清、任务规划、实现、测试、代码审查、简化和交付打包成可复用 skills，并提供 `/spec`、`/plan`、`/build`、`/test`、`/review`、`/code-simplify`、`/ship` 等命令入口。

- 偏完整交付流程：比单点 prompt 更像一套从想法到发布的工程操作手册，适合拿来做团队 agent 工作流基线。
- 跨工具适配：覆盖 Claude Code、Cursor、Gemini CLI、Windsurf、OpenCode、GitHub Copilot 和 Codex 等编码代理。
- 适合二次拆解：可以直接安装整套，也可以把其中的规范、评审、测试和交付流程拆出来改造成自己的项目规则。

[shadcn/improve](https://github.com/shadcn/improve)

`improve` 是一个面向 AI coding agent 的工作流型 Skill。它的重点不是直接改代码，而是先用更强的模型理解代码库、审计出真正值得做的问题，再把结论写成足够自包含的执行计划，最后把实现、测试和交付交给更便宜的模型或人去落地。

- 核心产物是计划而不是 patch：项目反复强调 `plan is the product`，主要输出落在 `plans/` 目录，而不是直接生成代码改动。
- 把判断和执行拆层：先做 `Recon`、`Audit`、`Vet`、`Prioritize`、`Plan`，把高成本智能集中花在审计和规划上，而不是边看边改。
- 入口覆盖完整闭环：除了 `/improve`、`/improve quick`、`/improve deep`、`/improve branch`、`/improve plan`，还提供 `review-plan`、`execute`、`reconcile`，把审计、执行和回收都串了起来。
- 计划是为弱执行者写的：示例计划会把代码摘录、允许修改的文件范围、验证命令、预期结果、out-of-scope 和 stop conditions 都写全，降低小模型乱发挥的概率。
- 很适合多 agent 协作和大仓库治理：尤其适合技术债梳理、分层用模、把 spec 与 implementation 解耦，以及把强模型预算集中花在判断而不是重复实现上。

[mattpocock/skills - 面向真实工程师的 AI coding skills](https://github.com/mattpocock/skills)

Matt Pocock 公开的 AI coding agent skills 集合，偏实战工程习惯沉淀，覆盖需求澄清、TDD、诊断、issue 拆分、架构改进等工作流。适合参考它如何把个人开发方法论拆成可触发、可复用的 agent 技能。

## 视觉创作 Skills

[antibes-holiday - 松弛黑色钢笔插画 Skill / Codex 插件](https://github.com/haorantang97/antibes-holiday)

一个可移植的视觉创作 Skill，面向原创的松弛黑色钢笔插画、叙事场景、表现性笔触和早期 Logo 探索。它不绑定或复刻某个具体品牌、插画家或既有 IP，而是把物理笔触、速记式识别、留白、非均衡比例和因果叙事等通用视觉语法整理成可执行工作流。

- 适合将产品机制、抽象概念或日常动作转成稀疏、有故事性的黑笔编辑插画，也可用于探索概念标记。
- 兼容 Codex 的内置图像生成与编辑流程；其他具备位图生成工具的 agent 也可使用。没有图像生成能力时，会退化为可直接交给渲染器的提示词与检查清单。
- 以 Codex 插件形式分发，包含 `SKILL.md`、笔触与构图参考、提示词配方及原创校准素材。可通过 `codex plugin marketplace add haorantang97/antibes-holiday` 后安装 `antibes-holiday`。
- 使用时应坚持其原创边界：借鉴线条和构图机制，不描摹来源图片、不保留标志性角色或构图，也不将结果宣传为第三方的官方风格。

[jakubkrehel/skills - 面向界面质量的 Agent Skills](https://github.com/jakubkrehel/skills)

一组专门帮助 Coding Agent 构建和审查高质量界面的 Skills，覆盖视觉细节、排版、颜色、无障碍、布局和 UX 文案。相比只强调“做得更好看”的单一提示，它把界面质量拆成六个明确领域，并提供 `better-interface` 作为统一审查入口。

- `better-interface`：协调其余六个 Skill，对页面、流程或功能做跨领域界面审查；支持 `quick` 和 `full` 两种模式，并按用户影响对问题排序。
- `better-ui`：聚焦圆角、阴影、图标、动效和微交互等 Design Engineering 细节，强调光学对齐、可中断动画和克制使用动效。
- `better-typography` 与 `better-colors`：分别处理字体选择、文本间距、换行与可读性，以及 OKLCH 调色板、对比度、色域和主题设计。
- `better-accessibility`：覆盖焦点状态、键盘操作、ARIA、表单、屏幕阅读器、点击区域和减少动态效果等无障碍要求。
- `better-layout` 与 `better-writing`：前者关注分组、对齐、阅读顺序、渐进披露和自适应断点，后者负责按钮、错误提示、设置项与空状态等界面文案。
- 审查流程强调证据：要求先识别项目技术栈与设计约定，再结合源码位置和实际界面状态给出分级结论，默认只审查、不直接修改代码。

安装全部 Skills：

```bash
npx skills add jakubkrehel/skills --skill '*'
```

只安装需要的 Skill，也可以运行 `npx skills add jakubkrehel/skills` 后交互选择。

[taste-skill](https://github.com/Leonxlnx/taste-skill)

一个面向前端视觉质量的 Agent Skills 集合，目标是减少 AI 生成界面里的模板感。它不是单个 `SKILL.md`，而是在 `skills/` 目录下提供多套可单独安装的 skill，覆盖高级 UI、动效、重设计、图片到代码、品牌板和移动端设计图生成。

- 默认入口是 `taste-skill`：适合做通用高质量前端，强调字体、颜色、布局变化、响应式、Tailwind/React/Next.js 约束和性能边界。
- 更强约束可用 `gpt-taste`：偏 Awwwards 风格，强调 AIDA 页面结构、GSAP 动效、宽幅排版和更激进的布局变化。
- 已有项目优先看 `redesign-skill`：它要求先扫描和诊断现有 UI，再按当前技术栈做有针对性的视觉升级。
- 风格型 skill 包括 `soft-skill`、`minimalist-skill`、`brutalist-skill`，分别对应柔和高级感、极简编辑型 UI、工业/终端/瑞士风格。
- 图像型 skill 包括 `imagegen-frontend-web`、`imagegen-frontend-mobile`、`brandkit`，只生成设计参考图，不直接写代码。
- 流程型 skill 包括 `image-to-code-skill` 和 `stitch-skill`，前者用于先生成设计图再还原代码，后者用于给 Google Stitch 生成 `DESIGN.md`。
- `output-skill` 用来约束模型完整输出，禁止用 `TODO`、`...`、`rest of code` 这类占位内容糊弄过去。

安装全部：

```bash
npx skills add https://github.com/Leonxlnx/taste-skill
```

只装单个 skill：

```bash
npx skills add https://github.com/Leonxlnx/taste-skill --skill "taste-skill"
```

使用建议：这套规则很有主观审美，适合作为前端视觉增强或设计探索的参考。落到已有业务项目时，不建议一次性混用多套风格 skill；优先按任务选择一个入口，例如新页面用 `taste-skill`，存量改版用 `redesign-skill`，只做设计图用 `imagegen-frontend-web` 或 `imagegen-frontend-mobile`。

[emilkowalski/skills - Design Engineer 的 UI 与动效技能集](https://github.com/emilkowalski/skills)

Emil Kowalski 面向 Design Engineer 的 agent skills 集合，包含 UI 与动效设计建议、动效评审与改进、动效词汇，以及提炼自 Apple 设计原则的 Web 设计规则。适合在生成或重构界面时补足设计判断，减少“能用但不够精致”的细节问题。

# UI Skills

Opinionated constraints for building better interfaces with agents.

## Stack

- MUST use Tailwind CSS defaults (spacing, radius, shadows) before custom values
- MUST use `motion/react` (formerly `framer-motion`) when JavaScript animation is required
- SHOULD use `tw-animate-css` for entrance and micro-animations in Tailwind CSS
- MUST use `cn` utility (`clsx` + `tailwind-merge`) for class logic

## Components

- MUST use accessible component primitives for anything with keyboard or focus behavior (`Base UI`, `React Aria`, `Radix`)
- MUST use the project’s existing component primitives first
- NEVER mix primitive systems within the same interaction surface
- SHOULD prefer [`Base UI`](https://base-ui.com/react/components) for new primitives if compatible with the stack
- MUST add an `aria-label` to icon-only buttons
- NEVER rebuild keyboard or focus behavior by hand unless explicitly requested

## Interaction

- MUST use an `AlertDialog` for destructive or irreversible actions
- SHOULD use structural skeletons for loading states
- NEVER use `h-screen`, use `h-dvh`
- MUST respect `safe-area-inset` for fixed elements
- MUST show errors next to where the action happens
- NEVER block paste in `input` or `textarea` elements

## Animation

- NEVER add animation unless it is explicitly requested
- MUST animate only compositor props (`transform`, `opacity`)
- NEVER animate layout properties (`width`, `height`, `top`, `left`, `margin`, `padding`)
- SHOULD avoid animating paint properties (`background`, `color`) except for small, local UI (text, icons)
- SHOULD use `ease-out` on entrance
- NEVER exceed `200ms` for interaction feedback
- MUST pause looping animations when off-screen
- MUST respect `prefers-reduced-motion`
- NEVER introduce custom easing curves unless explicitly requested
- SHOULD avoid animating large images or full-screen surfaces

## Typography

- MUST use `text-balance` for headings and `text-pretty` for body/paragraphs
- MUST use `tabular-nums` for data
- SHOULD use `truncate` or `line-clamp` for dense UI
- NEVER modify `letter-spacing` (`tracking-`) unless explicitly requested

## Layout

- MUST use a fixed `z-index` scale (no arbitrary `z-x`)
- SHOULD use `size-x` for square elements instead of `w-x` + `h-x`

## Performance

- NEVER animate large `blur()` or `backdrop-filter` surfaces
- NEVER apply `will-change` outside an active animation
- NEVER use `useEffect` for anything that can be expressed as render logic

## Design

- NEVER use gradients unless explicitly requested
- NEVER use purple or multicolor gradients
- NEVER use glow effects as primary affordances
- SHOULD use Tailwind CSS default shadow scale unless explicitly requested
- MUST give empty states one clear next action
- SHOULD limit accent color usage to one per view
- SHOULD use existing theme or Tailwind CSS color tokens before introducing new ones
