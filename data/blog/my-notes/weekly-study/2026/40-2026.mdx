### [咬紧牙关，把它发布出去](https://www.seangoedecke.com/grit-your-teeth-and-ship-it/)

本文核心是“咬牙发布”：构建能力与交付能力是两种不同技能，优秀品味会放大对不完美的痛苦，使人拖延；但无论编程还是写作，都必须偏向发布，接受瑕疵，靠持续产出和动量而非单次结果来提升成功率。

- 🧱 构建与交付是分开的技能，短期内甚至相互冲突；有构建天赋的人往往更不擅长交付。
- 🎯 Ira Glass 式差距：好品味让你看出作品不够好，但早期作品本就不可能达到你的品味标准。
- 🚢 唯一办法是“咬牙发布”，即使自己觉得作品很糟，也要先把它公之于众。
- 💻 优秀程序员追求优雅、正确、整洁，容易对缺陷产生情绪反应，因而迟迟不肯交付。
- 🏢 在大型软件系统中，缺陷无处不在；一致性常比局部完美更重要，有时甚至应复制非灾难性缺陷。
- 🧊 天赋高的人可能冻结、退到小范围“修正”、或羞愧拖延直至崩溃离职；差 diff 可改，没 diff 无法改。
- ✍️ 写作同理：对别扭句子和粗糙文笔敏感会让写作痛苦，但必须偏向发布，发布得越多越容易。
- 📈 无法预测什么会流行：作者不喜欢的一些文章反响很好，自认不错的文章却不受欢迎；高产比少而精收益更高。
- 🔄 成功不可控，应做“动量导向”而非“结果导向”：多做、看什么能留下，而不是死磕单篇至满意。
- 💡 不要过度珍惜点子；同一主题可以反复写直到写对，作者已写了约三十篇关于发布等主题的文章。
- 🏔️ 相关文章提醒“工程绝望谷”：每个项目都会有一段像要失败的低谷，优秀项目执行者要学会预期并忍受它。

### [Cloudflare 如何使用 AI 执行工程标准 | Cloudflare 博客](https://blog.cloudflare.com/engineering-standards-enforcement/)

Cloudflare 通过 Cloudflare Codex 将工程标准集中为可供人和 AI 代理检索、应用的治理化知识库，并让 AI 代理在代码审查、设计评审和事故报告审查中执行这些标准，以减少碎片化、尽早发现问题并保持一致性。

- 🧭 背景：工程指导分散在文档、仓库、聊天和个人经验中，查找耗时且可能过时，组织扩张后难以统一维护。
- 📚 Codex 按领域治理并采用 RFC 格式，由领域 owner 负责；使用 RFC 2119 的 SHOULD/MUST，批准后发布到内部 Astro 站点。
- 🔄 RFC 分 approved 与 enforced：approved 只产生非阻塞发现，enforced 的 MUST 违规可导致不批准或阻止合并，升级步骤给团队适应时间。
- 🧩 为避免上下文过载，代理把 SHOULD/MUST 提取为带稳定 slug 和元数据的 JSON，支持懒发现与渐进披露，未来将加入 SDLC 阶段等元数据。
- 🤖 AI 代码审查代理自今年初已标记近 230,000 次违规，其中近 16,000 次导致不批准或阻止合并。
- ⚡ 为减少等待，Cloudflare 提供与 Codex 对齐的 linter 包（TypeScript 已支持 oxlint，Rust 开发中，Go 后续），并支持本地 CLI 运行代码审查代理。
- 📐 规格审查代理在实现前评估技术设计，运行在 Workers、D1、AI Gateway 和 Cron Trigger 上；自 2026 年 5 月已审查近 600 个开放规格、超过 3,200 次调用。
- 📊 规格审查发现中 65% 为 major、29% 为 minor、6% 为 critical；未来将直接评论、支持人机对话并标记高影响提案供人工审查。
- 🚨 事故报告审查代理检查 postmortem 是否完整、解释清楚、记录贡献因素与解决措施并提出后续行动；自 2026 年 5 月已审查 200+ 报告。
- ✅ 被审查事故中 93% 为低影响、内部或预防性；高严重性事故中审查已强制，所有发现解决后报告才算完整。
- 🔭 未来将把 Codex 扩展到整个 SDLC，使代理更自主发现问题并提出修复，工程师保留审批；产品、安全、合规与信任安全团队也开始加入标准。
- 🚀 核心结论：AI 最有用之处是在工作点向工程师提供正确指导，从而更早发现问题并一致执行标准；Cloudflare 工程团队正在招聘。

### [Hallmark](https://github.com/nutlope/hallmark)

- 🎨 Hallmark 是面向 Claude Code、Cursor 和 Codex 的设计技能，目标是让产出拒绝“AI 生成感”；由 Together AI 制作。
- 🔁 现场演示包含 21 个主题、4 个动词，可按 T 循环切换。
- 🧱 它会为 brief 选择宏结构，套用 21 个主题之一，并运行 57 道 slop-test 关卡及发射前自批评。
- 🚫 拒绝 LLM 默认风格；不同 brief 生成的两页像不同网站，而不是同一模板换色。
- 🏗️ 默认动词：构建新 UI，选择宏结构、应用规则、返回前跑 slop test。
- 🔍 `hallmark audit <target>`：用反模式给现有代码打分，输出待办清单，不直接编辑。
- ♻️ `hallmark redesign <target>`：丢弃结构，保留文案、信息架构和品牌，用不同指纹重建。
- 🧬 `hallmark study <screenshot | URL>`：从欣赏的设计提取 DNA，如宏结构、字体搭配、色彩锚点；拒绝像素克隆和付费模板，可选生成 `design.md`。
- 🖼️ 示例覆盖应用、API、唱片、AI 工具、茶单、蜂蜜农场、印刷展、字体工作室、SaaS、旅行、时尚、基础设施等；每页自包含 HTML+CSS，CSS 注释标记宏结构。
- 🌐 完整示例可在 usehallmark.com 或 `site/_tests/` 浏览。
- 🧵 Custom NEW：当目录主题都不适配时，从零定制调色板、字体和布局，仍走 57 道测试，无底层模板；协议在 `custom-theme.md`。
- 📦 安装：`npx skills add nutlope/hallmark`，可重跑更新；也可复制 `SKILL.md + references/` 到 Claude Code、Cursor、Codex 对应目录。
- 📚 规则在 `SKILL.md` 和 `references/`，示例在 `docs/recipes.md` 与 `docs/study-examples.md`；MIT 许可，可自由使用、fork、发布。

### [magpie](https://usemagpie.ai/)

magpie 是一款免费、开源、原生的本地 AI 网关工具，运行在你自己的机器上（127.0.0.1:3425），可同时兼容 OpenAI、Anthropic 和 Google Gemini 等各家 API 协议，并双向翻译（含流式输出、工具调用与推理），让任意 AI 编程代理都能调用任意厂商的模型。它提供菜单栏界面、智能路由、订阅共享、多账号故障转移、逐代理用量统计，并附带 TUI 与 CLI，支持 macOS、Windows 和 Linux。

- 🌐 一个网关，通晓所有 API：Codex 只会说 OpenAI Responses，Claude Code 只会说 Anthropic Messages，magpie 在本地做双向翻译，任何代理都能用任何厂商的模型。
- 🖥️ 菜单栏管理：一眼看清每个代理当前用的模型，点击即可修改，magpie 只重写你改动的那个配置键，下个会话生效。
- 🔁 一键还原：选择原生模型时，magpie 会精确恢复原有配置；配置档案（Profiles）可一次性切换所有代理。
- 🔑 订阅共享：已登录的代理账号会变成一个 provider，其模型出现在其他代理的选择器中，无需复制或粘贴密钥，令牌按原代理方式刷新。
- 🧠 智能路由：为每轮对话按意图（如"快速提问""写测试"）分配最合适的模型，由一个小而快的分类模型判断，工具调用轮次保持在同模型上。
- ⚖️ 多账号与故障转移：可同时启用多个 Claude、ChatGPT、Copilot 或 Grok 账号，优先使用最早重置额度的账号，余额耗尽或限流的账号自动跳过，失败时在你看到错误前就已重试。
- 📦 供应商预设：20 个预设覆盖厂商、中转和本地服务器，粘贴密钥即可完成配置，新发布的模型会在下次刷新时自动出现，密钥只留在 magpie 中。
- ✂️ 细致且无侵入：config 编辑保留注释、顺序与缩进，写入是原子的；程序小于 15 MB，使用系统原生 webview，无 Electron 无运行时。
- 🔒 安全与开放：MIT 许可、代码在 GitHub 上，从不从环境变量读取 API 密钥；Mac 版本经过签名与公证，并支持静默自动更新。
- 📊 用量统计：按代理和模型查看 token、缓存命中与花费。
- 💻 终端支持：提供 TUI 和 CLI，安装脚本会把 `magpie` 命令放入 `~/.local/bin`；支持 `provider add`、`codex`、`claude`、`gemini`、`group add`、`ls`、`save/use`、`tui` 等命令；Windows 上 `magpie.exe` 命令一致，另有纯终端构建版本。

### [Submarine — Modern SSH & SFTP Client](https://github.com/SinaXhpm/Submarine)

Submarine 是一款免费、开源、快速且安全的 SSH/SFTP 客户端，支持 Windows、macOS、Linux 和 Android。它基于 Rust + Tauri 构建，用一个原生标签窗口整合终端、SFTP、端口转发、文件夹镜像、Docker 管理、服务器信息和加密配置同步，目标替代 PuTTY + WinSCP + 隧道管理器的组合，MIT 许可。

- 🚀 免费开源，MIT 许可；Rust + Tauri，启动快、内存约 80 MB，非 Electron。
- 🖥️ 跨平台：Windows、macOS、Linux（.deb/.rpm/Arch/AppImage）和 Android 8.0+（APK 侧载）。
- 🧩 每台服务器一个标签窗口，集成终端、SFTP、隧道、文件夹镜像、Docker、信息和命令库。
- 👥 支持分屏查看两台会话、全局 Wall 网格看板，以及广播输入到多个会话。
- 💻 终端支持 xterm.js 真彩色、鼠标、选择复制、右键粘贴、断线重连缓冲和容器 shell。
- 📁 SFTP 双窗格拖放、多选、过滤、覆盖确认、远程实时编辑、权限编辑和直接下载。
- 🔄 文件夹镜像支持双向同步、内容哈希比较、实时监听、冲突策略和软删除到 .submarine-trash/。
- 🐳 Docker 管理器支持容器启停、实时日志、统计、资源、Compose 查看、安全 prune 和 exec 终端。
- 🌐 端口转发支持本地 -L、远程 -R、动态 -D，以及 SOCKS/HTTP 代理。
- 📊 服务器信息面板展示系统、网络、端口、服务，并可启停 systemctl 服务。
- 🔐 零知识云同步：本机 Argon2id 派生密钥，AES-256-GCM 加密，服务器仅存密文；无注册和密码找回。
- 🛡️ 安全默认：TOFU 主机密钥与 nonce 绑定、严格 CSP、最小 Tauri ACL、零化主密钥。
- 📦 支持从 PuTTY、MobaXterm、OpenSSH config 和 Submarine JSON 批量导入配置。
- 📱 Android 版复用同一 Rust 核心和加密保险库，提供触控终端软键、SFTP、端口转发；文件夹镜像暂仅桌面端。
- ⚙️ 其他功能：快捷命令、每节点笔记、自动启动、资源监控、快速连接、离线使用、无遥测。
- 🏗️ 技术栈：React 18、TypeScript、Tailwind、xterm.js、Rust、Tauri 2、russh、rusqlite、aes-gcm、argon2、zstd。
- 📥 安装包覆盖主流平台，但当前构建未签名，Windows/macOS/Android 需手动允许或去除隔离。

### [terminal-browser](https://github.com/zenbu-labs/terminal-browser)

- 🖥️ terminal-browser 是一个可在终端内运行的真实浏览器，基于 Chromium，支持在终端中显示网页并与其交互。
- 📦 支持 curl 安装：`curl -fsSL https://terminal-browser.sh/install | bash`，并用 `terminal-browser upgrade` 升级。
- 🍺 支持 Homebrew 安装：`brew install terminal-browser`。
- 🤖 提供 Claude Code 插件，安装说明见原文链接。
- 🚀 常用命令：`terminal-browser` 启动，`terminal-browser open <url>` 打开网址，`--split right` 右侧分屏。
- 🔐 支持 `terminal-browser open --ssh <user@host> <url>`，通过远程服务器代理所有网络请求。
- 📋 管理命令：`ls` 列出已打开浏览器，`action` 提供与 agent-browser 兼容的 CLI，`upgrade` 升级版本。
- 🧑‍💻 让编码 agent 和网站共享同一终端标签。
- 🌐 让 agent 完全访问已打开的终端浏览器，从而具备使用网页的能力。
- 📄 让 agent 生成 HTML 计划，并自动在终端浏览器分屏中打开。
- 🔗 通过 SSH 轻松预览远程机器上运行的网站。
- ⌨️ 提供 macOS/Linux 快捷键：退出、新标签、编辑 URL、命令面板、页内查找、刷新、前进/后退、缩放、Devtools、复制/粘贴/剪切、录制页面、元素选择、关闭弹窗等。
- 🖼️ 依赖支持 kitty graphics protocol 的终端，如 ghostty、kitty、cmux、VS Code 等，用于在终端显示像素。
- ⚡ 使用 Electron 离屏渲染 API 从 GPU 直接读取 Chromium 像素，实现流畅渲染且不丢帧。
- 🖱️ 监听终端鼠标和键盘事件并发送合成事件给 Chromium；终端无法获取的输入由后台 Swift 应用非侵入读取，支持平滑滚动和触控板事件。
- 🦀 外层 UI 由 Rust 图形引擎构建，React 自定义渲染器和 TypeScript 定义界面；浏览器 UI 与内容绘制到同一共享 canvas。
- 📚 底层能力已抽象为 JS 库 `pixel`：https://github.com/zenbu-labs/pixel。
- 🔗 SSH 推荐使用 `terminal-browser --ssh <ssh arguments>`：网站本地运行，网络请求经 SSH 由远程机器代理，可加载远程 localhost 网站。
- 🧩 支持嵌入现有 TUI，参考 `examples/embedded`。
- 🐧 路线图：Linux 支持已完成 ✅，后续包括 Chrome 扩展和设计模式。

### [TBM 440：将人分门别类的问题](https://cutlefish.substack.com/p/tbm-440-the-problem-with-putting)

本文批判职场中把人塞进人格类型、优势标签或“文化契合”盒子的做法，认为静态标签无法说明人在不同情境、激励、权力动态与文化规范下会如何表现。作者借大五人格示例和个人经历指出，组织常把既有规范自然化，把适应负担推给个体，尤其边缘群体；所谓勇气、主人翁等美德也常被窄化为特定文化表达。真正有用的，是理解触发行为切换的条件与假设。

- 🧩 人格与“优势”测试虽有趣，却难指导日常工作，也无法替代真正了解他人及情境反应。
- 🏟️ 团队建设常借用运动队或“文化契合”隐喻，但容易把现有文化美化成“果断、协作、高主人翁”等抽象优点。
- 🏷️ 给人贴“战略型、人际型、高尽责、低宜人”等标签很方便，却压缩复杂性并忽略情境差异。
- 🔍 更该问的不是“你是什么类型”，而是“在什么条件下你会切换模式，依据哪些区分？”
- 🧪 同为高尽责、低神经质的人，面对会议节奏问题可能做出相反选择，因对可逆性、证据、权威与实验标准理解不同；高尽责 + 高宜人也可能表现迥异。
- 🎭 作者自述：多数时候重视共同设计与行动偏向，但遇到权力滥用、泛化或贬低他人时，会迅速进入捍卫者模式，显得直接对抗；外部矛盾，内部一致。
- 🏢 组织规范是行为的沉淀，却被去个人化为“这里就是这样”；受益者视其为自然，适应者却承担调整、读空气与融入的个人负担。
- ⚖️ 适应负担不均，常最重地落在双重代表性不足者身上，他们更少拥有定义“正常”的权力。
- 🦁 “勇气、纪律、行动偏向、主人翁”看似普世，组织实际奖励的是特定表达；同一行为在不同文化中可能被视为勇气或不尊重。
- 🧭 结论：类型只提示重心或惯性；理解情境触发因素、注意到的差异及对风险、权威、公平、可逆性、责任的假设，才更能预测合作实际会怎样。

### [我不想要细节 | michaelheap.com](https://michaelheap.com/i-dont-want-the-details/)

一次与工程高管的通话点明核心：复盘的目标不是解释“为什么发生”，而是确认“我们要改变什么”，让同类失败更不容易重演。

- 🚫 高管说“我不想知道细节”，并非轻视，而是表达信任：他相信团队是称职的，重点应转向下一步改变。
- 🧩 多数组织事故后问“为什么发生”，容易写出合情合理的时间线，但理解问题不等于解决问题，甚至会削弱改变的紧迫感。
- 🔄 更有效的问题是：“我们要改变什么，让同一类失败下次更不可能发生？”
- 🧠 前提是假设“合理的人也会造成这个结果”，然后追问系统需要怎样调整，而不是责怪个人。
- 🗂️ 例如：有人休假导致归属不清，就明确无人可用时的责任归属；需求临近发布变更，就设计发布窗口内的变更机制；告警太多导致疲劳，就提升告警信噪比。
- 🛠️ 好的解释不是修复；若复盘只写“更早通知支持”“加强沟通”“下次更小心”，那只是愿望，不是行动。
- 🧪 判断修复是否有效：如果相关人员明天都离职，这个修复还能生效吗？不能，则系统仍然注定失败。
- ❓ 有效复盘应问：“如果明天发生同样情况，什么会导致不同结果？”能强制决策的流程是改进，能阻止同类错误的系统更强。
- ⚖️ 也不要为每个失败都造新流程；要有意识地接受某些风险，而不是用“我们会更努力”来自我安慰。
- 🤝 共情不应成为组织免除改变责任的机制；人通常是在信息、激励和约束下做出当下最好的决定，所以修复人往往是错误答案。
- 💬 领导者最有用的表态是：“我相信你。我不需要细节。告诉我，我们要改变什么。”
