### [mdxcn：Markdown 友好组件](https://www.mdxcn.dev/?ref=tailwindweekly.com)

- 🧩 mdxcn 提供面向 MDX 的 Markdown 友好组件，包括提示框、时间线、表格和用文本字符绘制的图表。
- 📝 在 MDX 文件中，这些组件以标签内 Markdown 的形式编写；在 README 或 PR 中，则把同一图形作为代码块粘贴。
- ⚙️ 安装命令为：`pnpm dlx shadcn@latest add https://mdxcn.dev/r/all.json`，也可让 agent 使用同一库。
- 🤖 安装 agent skill 后，agent 能选择图表、填入真实 props，并把图表放在正文旁。
- 🛠️ Agent 可输出 MDX 的 JSX、用于 comark 的 `::graph-*`，或 knap 过滤器。
- 📄 在纯 Markdown 中，agent 会粘贴官方 ASCII 图形，而不是自创无法复用的图表。
- 🔍 mdxcn 是一个 React 图表与文本字符图集合，每个组件都可访问、可主题化，并适合与 Markdown 正文并排展示。
- ❓ 文档还涉及：在哪里使用、如何安装图表、agent 如何知道选哪个图表、agent 能否后续编辑结果，以及是否有 API。
- 📚 用户可以浏览库中的全部组件，并了解安装内容、适用场景与 agent 使用方式。

### [跨团队协作](https://kore-nordmann.de/blog/cross_team_collaboration.html)

本文探讨跨团队协作为何常被组织自身的绩效指标破坏：当各团队只优化自身产出，跨团队帮助就变成隐形、无回报的工作，最终导致整体交付变慢、关键连接者流失；作者建议给团队留白，并公开奖励跨团队协作。

- 🗣️ 当“因为另一个团队，我们无法交付”成为常态，问题通常不在团队，而在组织指标。
- 📉 过度优化每个团队的局部速度，会杀死公司整体交付能力：团队局部最优，整体却挨饿。
- 🎯 按团队产出考核和奖励，等于奖励“不帮助其他团队”；帮忙不增加本团队数字，反而拖累自己。
- ⚖️ 这是古德哈特定律：指标一旦变成目标，就不再衡量真正重要的事。
- 🕳️ 跨团队解困工作没有工单、看板或仪表盘记录，在只衡量可见产出的系统中会悄悄消失。
- 🧠 最擅长跨团队连接、理解业务需求的人，往往被逼走或耗尽，组织因此失去“连接组织”。
- 🌱 对策一：给团队刻意留白；满负荷运转的团队没有余力帮助别人，留白才带来响应力。
- 📣 对策二：公开看见并奖励跨团队帮助；管理者公开表扬比口头号召协作更有效。
- 🌐 分布式团队更依赖刻意安排：远程没有走廊和茶水间偶遇，留白与连接者更重要。
- 🏢 若组织坚持衡量比较每个团队和个人的产出，就会得到局部最优但无法跨团队交付的公司。
- 📚 本文属于作者反思 SaaS 产品公司融资、增长与出售经历的系列，并附有软件架构、远程文化、技术团队管理等延伸主题。
- ✅ 总结：听到重复抱怨时不要先怪团队，那往往是你自己的指标在回话。
